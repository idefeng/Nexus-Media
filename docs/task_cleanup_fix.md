# 任务总结：清理助手 Bug 修复与性能优化

## 问题背景
用户反馈“清理助手”页面点击后程序未响应（卡死）。经排查，主要原因是：
1. **算法复杂度过高**：相似度检测在 20,000+ 张图片规模下触发了 $O(N^2)$ 的暴力比对，计算量达数亿次。
2. **内存溢出 (OOM)**：Node.js 进程在一次性加载数万条包含 Embedding 的数据库记录时触发了 V8 内存限制。
3. **主线程阻塞**：重型计算在主进程同步执行，导致事件循环卡死。
4. **UI 重叠**：原有的“刷新”浮动按钮与操作区发生布局冲突。

## 修复与优化方案

### 1. 算法与性能优化
- **引入时间窗口**：在 `cleanup.ts` 中将比对范围限制在拍摄时间相差 2 小时内的图片，大幅降低计算量。
- **激进式扫描 (Radical Streaming)**：将分析逻辑改为增量推送。后端每计算出 100 张图片的相似结果就立即发送给前端显示，极大地提升了响应感知速度。
- **真分页读取**：重构数据库接口支持 `LIMIT` 和 `OFFSET`，确保内存占用恒定，彻底解决 OOM 崩溃问题。

### 2. UI/UX 改进
- **布局调整**：移除了右下角的浮动按钮（FAB），将“刷新”功能整合进顶部标题栏（TopBar），修复了重叠问题。
- **实时反馈**：重构了 `CleanupDashboard` 的状态管理，使其能够实时响应后台推送的扫描进度和结果。
- **国际化修复**：补全了中文环境下缺失的应用标题与副标题翻译。

### 3. 代码健壮性
- **依赖修正**：移除错误的 `axios` 引用，改用原生 `fetch`。
- **接口纠错**：修正了调用 AI 后端清晰度检测时的接口路径。

## 提交文件列表
- `electron/database.ts`: 增加分页支持与统计接口。
- `electron/cleanup.ts`: 重构相似度分析逻辑，支持子集检测。
- `electron/main.ts`: 实现流式扫描器与分页调度。
- `electron/preload.ts`: 增加新事件监听接口。
- `src/vite-env.d.ts`: 同步类型定义。
- `src/App.tsx`: 移除 FAB，优化状态轮询。
- `src/components/layout/TopBar.tsx`: 重新布局功能按钮。
- `src/components/cleanup/CleanupDashboard.tsx`: 支持增量数据展示。
- `src/locales/zh/translation.json`: 补全翻译。

### 4. 视觉排版优化
- **中西文混排优化**：在 `tailwind.config.js` 中定制了以 'HarmonyOS Sans SC' 为核心的字体族，解决了 Windows 平台渲染不清晰的问题。
- **排版规范化**：在 `src/index.css` 中统一了全局行高（1.5）与字体平滑选项，显著提升了大数据量列表下的阅读舒适度。
